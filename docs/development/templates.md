# Template implementation

The pure parser/renderer is `crates/core/src/template.rs`; the thin `crates/template-wasm` crate exports its owned-buffer ABI. Keep the core an rlib: mixing a core cdylib with separate desktop/workspace feature graphs can overwrite un-hashed build outputs in a shared Cargo target directory.

Content remains envelope version 1 with `type: template`, source text and variable definitions. Unknown non-reserved identifiers are text fields. Date/time/timestamp key:enter and cursor:here are reserved. Rendering is one pass: answers and defaults are never parsed as source. The template renderer receives one timestamp and local UTC offset, so evaluation has no IO.

Sync protocol 6 prevents old desktops exchanging rich-text records or assets they cannot retain. Public API routes stay v3. Code and legacy plain_text remain literal; Text uses the template renderer. Browser runtime answers only go to the local WASM module; native answers only go to the local Rust runtime and private IPC. No runtime answers are persisted or synchronized.

Omarchy snapshots retain stable identity/revision and a precomputed prompt flag. Immediate templates render on a worker while following typing is buffered through the existing insertion path. Prompted matches send a PID-validated notification before any erasure. The panel requests preparation using the original event deadline and input generation; only then does it open the fill form. Completion sends a fresh request after confirmation.

Private notifications remain datagrams; insertion uses a bounded Unix stream so long values cannot exceed a datagram limit. The service revalidates identity/access before each ordered text/Enter step. Acknowledgments carry input/context generation, preventing later steps after interruption. No completed Enter action is retried. Clipboard ownership/restoration uses the existing paste implementation.

Tests: core parser/clock/literal handling, SQLite metadata/snapshot identity, TUI dialogs, server import/move/conflict/Trash preservation, two offline clients, protocol rejection, real browser WASM/editor/fill/copy, and native panel controls. `scripts/template-smoke.py --live` requires explicit idle authorization, uses temporary data and disposable windows, and restores the original service/panel/focus.

`Rendered.cursor` is optional metadata: the marker’s UTF-16 offset plus suffix UTF-16 and grapheme counts. The source remains unchanged for sync/export; output text/steps omit the marker. Validation rejects duplicates, explicit Enter actions, Rich text and positions inside a rendered grapheme, including clusters formed by filled values. Older parsers reject the colon syntax. Clipboard payloads carry cursor metadata; confirmation Enter is consumed for marked snippets, and native movement occurs before buffered typing is released. No-marker serialization omits the field; deserialization defaults it to absent.

Browser input/textarea and Android selection use UTF-16 offsets; Notepad’s direct replacement also accounts for CRLF. Chrome contenteditable and generic native desktop paths move backward by graphemes using the editor’s character navigation. iOS uses a UTF-16 offset through UITextDocumentProxy, consistent with UIKit text-position offsets; host behavior still requires device acceptance testing. These host APIs can differ for bidi text, editor-specific arrow handling and pasted newline normalization. Cursor movement checks the existing target/generation/interruption state; failure never retries insertion. Copy ignores cursor metadata and reports the omission without changing text usage counts.

Generic native and Omarchy cursor movement has no suffix-length cap or fixed total movement deadline. Linux tracks remaining movement in constant space, keeps the idle clock alive on progress, and waits for movement completion or service disconnection instead of a fixed IPC timeout. The existing worker stall watchdog remains active. Native input epochs cancel marked insertion/movement regardless of the trigger key, while TypeRelay injected events and captured macOS following typing are excluded. Omarchy emits cursor strokes incrementally, polling context and buffering input between strokes; acknowledgment follows the final stroke.
